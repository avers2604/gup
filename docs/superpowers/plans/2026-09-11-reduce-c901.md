# C901 Complexity Reduction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the 13 currently reported C901 violations to the configured threshold without changing user-visible behavior.

**Architecture:** Refactor by extracting small, responsibility-focused helpers rather than changing data flow or UI semantics. Backup/restore is split into staging, validation, database-path migration and atomic apply/rollback; UI orchestration functions are split into worker, error-reporting and view-update helpers. Existing public function signatures remain stable.

**Tech Stack:** Python 3.13/3.14, Tkinter, SQLite, pytest, flake8/mccabe, GitHub Actions.

**Spec:** Follow-up to PR #37 reliability audit; CI currently reports 13 C901 findings with `--max-complexity=10`.

## Global Constraints

- Preserve all existing public function signatures and Russian UI copy unless a test requires otherwise.
- No new runtime dependencies.
- Keep Python 3.13 and 3.14 green.
- Keep pytest coverage at or above 60%.
- Keep Bandit medium/high, pip-audit, CodeQL and Gitleaks green.
- Make complexity reduction structural; do not hide C901 with `# noqa: C901`.
