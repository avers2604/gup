# Приёмочные испытания GET-Passes 1.1.0

Этот документ разделяет автоматическую и физическую приёмку. GitHub Actions подтверждает программные сценарии на Windows, но не может достоверно проверить конкретный рабочий принтер, его драйвер, лоток, ориентацию бумаги и фактический дуплекс.

## A. Автоматическая приёмка — GitHub Actions

Для каждого PR в `main` workflow `Windows PR smoke` обязан пройти следующие этапы:

- [x] полный `pytest` на `windows-latest`;
- [x] сборка `GET-Passes.exe` через PyInstaller;
- [x] запуск packaged EXE с `--self-test`;
- [x] сборка `GET-Passes-Setup.exe` через Inno Setup;
- [x] тихая установка Setup.exe во временный каталог;
- [x] запуск установленного EXE с `--self-test`;
- [x] тихое удаление приложения;
- [x] проверка, что установленный EXE удалён.

Linux CI дополнительно проверяет Python 3.13/3.14, strict flake8, C901, pytest coverage, `pip-audit` и Bandit. Security workflow проверяет CodeQL и Gitleaks.

## B. Приёмка на рабочем ПК без принтера

Использовать кандидат из GitHub Release/Actions, а не локальную непроверенную сборку.

- [ ] Установить `GET-Passes-Setup.exe` обычным способом.
- [ ] Убедиться, что ярлык в меню «Пуск» запускает приложение.
- [ ] Проверить запуск после перезагрузки Windows без установленного Python.
- [ ] Создать тестовый пропуск ТС и сохранить PDF.
- [ ] Создать тестовый бейдж с фотографией и сохранить результат.
- [ ] Закрыть и снова открыть приложение; убедиться, что настройки и журналы сохранились.
- [ ] Проверить окно «Незавершённые выдачи»: готовый документ, отсутствующий документ, отмена операции.
- [ ] Создать резервную копию, затем восстановить её в тестовом наборе данных.
- [ ] Проверить, что данные находятся вне `Program Files` (обычно `%LOCALAPPDATA%\GET-Passes`).
- [ ] Удалить приложение через Windows Settings/Programs and Features.
- [ ] Убедиться, что пользовательская БД/резервные копии не удалены вместе с программой.

## C. Физическая приёмка на целевом принтере — ОБЯЗАТЕЛЬНО ВРУЧНУЮ

Зафиксировать модель принтера и версию драйвера:

- ПК / подразделение: __________________________
- Принтер: _____________________________________
- Драйвер / версия: _____________________________
- Windows / build: ______________________________
- Дата проверки: ________________________________
- Проверяющий: __________________________________

Сценарии:

- [ ] Печать одного пропуска ТС в фактическом размере без масштабирования драйвером.
- [ ] Печать A4 с двумя пропусками: геометрия, линия разреза, поля листа.
- [ ] Печать A5, если режим используется на рабочем месте.
- [ ] Автоматический дуплекс: лицевая и оборотная стороны имеют правильную ориентацию и совмещение.
- [ ] Ручной дуплекс: подсказка понятна, после перекладки листа оборот печатается в правильной ориентации.
- [ ] Печать бейджа в используемом на рабочем месте режиме.
- [ ] Массовая печать: порядок страниц соответствует входным данным.
- [ ] При отмене задания в приложении журнал не подтверждает невыданный документ.
- [ ] При ошибке/отсутствии принтера приложение показывает понятную ошибку и не теряет восстановимую операцию.
- [ ] После успешной печати запись появляется в нужном журнале ровно один раз.

## D. Критерий допуска stable release

Stable versioned release допускается к эксплуатации, когда:

1. все автоматические workflow зелёные;
2. Authenticode-подпись `GET-Passes.exe` и `GET-Passes-Setup.exe` имеет `Status: Valid`, если организация требует доверенную подпись;
3. раздел B пройден на целевом рабочем ПК;
4. раздел C пройден на целевом принтере;
5. найденные отклонения либо исправлены, либо формально приняты ответственным лицом.

До выполнения B/C GitHub CI подтверждает программную готовность кандидата, но не физическую готовность рабочего места.
