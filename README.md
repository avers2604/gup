# Система выпуска пропусков — СПб ГУП «Горэлектротранс»

Настольное приложение для оформления пропусков на транспортные средства
и постоянных пропусков (бейджей) работников: заполнение, предпросмотр,
печать, журналы выдачи, реестры и массовая печать из Excel/CSV.

## Запуск

```
pip install -r requirements.txt
python pass_generator.py
```

Требуется Python 3.10+ с `tkinter` (входит в стандартный установщик для Windows).

## Файлы рядом с программой

| Файл | Назначение |
|---|---|
| `assets/logo_get.png` | фирменный знак ГЭТ. Единственный растровый элемент бланка |
| `app_icon.ico` | иконка окна |
| `fonts/` | брендбук-шрифт (`Moscow Sans` или `Echoes Sans`) и `DoT Icons`. Каталог может называться и `fronts/`. Необязательны |

Бланк пропуска на ТС **строится кодом** (`getpass_core/blank.py`) — внешний
`template.png` больше не нужен. Разметка снята с типографского бланка и
задана координатами; чтобы поправить макет, правьте константы блоков в этом
модуле, а не картинку.

Логотип намеренно оставлен растровым: официальный знак не воспроизводится
вручную. Если появится версия в большем разрешении — положите её вместо
`assets/logo_get.png`, ничего больше менять не нужно.

## Где хранятся данные

Каталог выбирается автоматически при запуске:

1. `data/` рядом с программой — если туда можно писать;
2. каталог программы — если там уже лежат журналы прежней версии;
3. `%LOCALAPPDATA%\GET-Passes` — если запись рядом с программой запрещена
   (например, установка в `Program Files`); файлы прежней версии переносятся.

В каталоге данных: `settings.json`, журналы (`.csv` + `.xlsx`), база машин,
`photos/` с фотографиями бейджей, `crash.log`.

> **Персональные данные.** Журналы и фотографии содержат ФИО, телефоны,
> госномера и изображения сотрудников. При первом запуске программа
> ограничивает доступ к каталогу данных текущим пользователем. Резервная
> копия — обычный ZIP **без шифрования**: храните её на носителе с
> ограниченным доступом.

## Структура

```
pass_generator.py     точка входа
getpass_core/         предметная логика, без Tkinter — импортируется и тестируется отдельно
  domain.py             даты, номера бланков, госномера
  config.py             пути, каталог данных, настройки, вычистка ПДн из crash.log
  storage.py            журналы (единая реализация для ТС и бейджей), база машин
  fonts.py              шрифты бланков, Echoes Sans, DoT Icons
  render.py             отрисовка пропуска, бейджа, листов А4
  registry.py           печатные реестры (единая реализация)
  pdfwriter.py          потоковая запись многостраничного PDF
  printing.py           печать через Windows, сохранение документов
  backup.py             резервное копирование и восстановление
getpass_ui/           интерфейс Tkinter
  app.py                главное окно
  pass_tab.py           форма пропуска на ТС
  badge_tab.py          форма бейджа
  journal.py            окно журнала (одно на оба журнала)
  crop_window.py        кадрирование фотографии
  batch.py              массовая печать
  widgets.py            общие элементы
tests/                автотесты
```

## Мониторы с высоким разрешением

Приложение объявляет себя DPI-осведомлённым (Per-Monitor v2), поэтому при
масштабе Windows 125/150/200% интерфейс становится крупнее, а не мыльнее.
Размеры окон пересчитываются под масштаб и ужимаются под рабочую область
экрана, чтобы нижние панели с кнопками не уходили под панель задач.

## Тесты

```
pip install -r requirements-dev.txt
python -m pytest                    # логика, хранилище, отрисовка, PDF
xvfb-run -a python -m pytest        # + headless-проверка интерфейса (Linux/CI)
python -m pyflakes pass_generator.py getpass_core getpass_ui
```

`pyflakes` ловит обращения к неопределённым именам до запуска — именно
такой ошибкой (`NameError` на обработчике кнопки) программа падала раньше.

## Сборка .exe

```
pyinstaller --onefile --windowed --icon app_icon.ico pass_generator.py
```

Рядом с полученным `.exe` положите `template.png`, `app_icon.ico` и `fonts/`.
